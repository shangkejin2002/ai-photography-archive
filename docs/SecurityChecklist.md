# 上线前安全检查清单

## 秘密与配置

- [ ] 数据库地址、账号、密码只通过环境变量或秘密管理服务注入。
- [ ] 仓库、构建日志、部署脚本和镜像中不存在真实密码、Token 或私钥。
- [ ] 生产环境使用 `prod` profile，并为 `DB_URL`、`DB_USERNAME`、`DB_PASSWORD` 设置独立生产值。
- [ ] 定期轮换数据库凭据，并遵循最小权限原则授权数据库账号。

## 数据与接口

- [ ] 所有用户接口返回 `UserVO`，不直接序列化数据库实体。
- [ ] 响应中不包含 `userPassword`、`phone`、`email` 等页面不需要的字段。
- [ ] 管理员查询和删除接口均在服务端校验管理员 Session，不能只依赖前端路由保护。
- [ ] 删除为逻辑删除；执行前确认目标 ID，并保留必要的审计记录。

## Session 与 Cookie

- [ ] Cookie 设置 `HttpOnly=true`、`SameSite=Lax`。
- [ ] 生产 HTTPS 环境保持 `Secure=true`；只有本地 HTTP 调试时才允许临时设为 `false`。
- [ ] 登录成功后更换 Session ID，注销时使 Session 失效。
- [ ] Nginx 与应用在同一站点下提供页面和 `/api`，避免不必要的跨域配置。

## 日志与监控

- [ ] 不记录密码、完整 Cookie、Session ID、数据库连接串或其他敏感信息。
- [ ] 记录登录失败、无权限访问、管理员删除等安全事件，但对外响应不泄露内部堆栈。
- [ ] 为异常率、登录失败率、可用性和数据库连接池设置监控与告警。

## 滥用防护与 CSRF

- [ ] 在网关或应用层对注册、登录等接口实施按 IP/账号限流与失败退避。
- [ ] 部署后根据业务风险评估 CSRF Token；`SameSite=Lax` 是基础防护，不替代完整 CSRF 方案。
- [ ] 校验 `Origin`/`Referer` 的策略与真实域名一致，不使用允许凭据的通配 CORS。
- [ ] 设置 HTTPS、HSTS、合理的安全响应头，并限制请求体大小。

## 依赖与发布

- [ ] 发布前运行后端测试/打包和前端锁文件安装/构建。
- [ ] 扫描 Maven、pnpm 依赖与基础系统的已知漏洞，并制定升级周期。
- [ ] 数据库变更和应用发布均有备份、回滚步骤与经过验证的恢复方案。
